# AGENTS.md

## General Guidelines

* Follow the formatting guidelines of this project.
  * Don't randomly comment.
  * Read code sorrounding your change to copy its styling.
* Never hardcode RSS/Torznab sources.
* Use simple, one-line commit messages (if you don't understand the style, you may want to see it with `git log --oneline -n 10` yourself) with [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/) identifiers.
  * Only commit if either the user asks or a task is truly done; if something has been implemented by not verified by the user, never commit.
  * Before you name a commit, ask the user if they are fine with your given name.

## Development Workflow

* While developing, run only `cargo run` as to not trigger a really long, CPU-killing build process with `cargo run --release`. `cargo check` is usually enough if you want to see only if a project compiles over if a feature works. `cargo test` is also usually a very good replacement for running things in release mode.
* Run `cargo fmt` when a task is done.
* When something is ready for release (this doesn't mean when a task is done; it is up to the user to decide this), compile with `cargo --release` and test compilation on platforms for which the compiler toolchain is available locally; report the full platform set: what completed and what didn't (and if it didn't because the toolchain is not available).

## Mobile

The Android app lives in `mobile/` (Expo, React Native), sharing code with `web/` through `packages/shared`; all three are bun workspaces installed from the root (`bun install`).

* Required tools: the Android SDK (`ANDROID_HOME`), JDK 17 (or 21), the NDK pinned in `mobile/app.config.ts` (`NDK`), Rust with the `aarch64-linux-android` and `x86_64-linux-android` targets, and `cargo-ndk` (`cargo install cargo-ndk`).
* While developing, use `cd mobile && bun run android` (a debug build with Fast Refresh) on a device or emulator. Never run release builds (`bun run release`) during development.
* `bun run typecheck` and `bun run test` (in `mobile/` and `packages/shared/`) are the quick checks. After the schema changes, run `bun run codegen` in `packages/shared/`, `web/` and `mobile/`.
* Never commit `mobile/android/` (or `mobile/ios/`): it's generated by `expo prebuild`. Native changes go through config plugins (`mobile/plugins/`) and local Expo modules (`mobile/modules/`). Rust crates for the app go in `mobile/crates/`, a Cargo workspace of its own (`mobile/Cargo.toml`) so the server and the app don't rebuild each other, and are built into a module with `mobile/gradle/rust.gradle`.
* Effects (`mobile/src/effects/`), haptics (`mobile/modules/haptics`) and theme tokens (`mobile/src/theme/`) are shared by every screen; use them rather than making new ones.
* The app's version is the server's: when bumping the version, change the workspace version in `Cargo.toml`, `mobile/Cargo.toml`, `web/package.json`, `mobile/package.json` and `packages/shared/package.json` together.
